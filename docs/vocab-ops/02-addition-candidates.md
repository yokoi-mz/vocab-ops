# 02 追加候補

## 何をするか

手札語彙に足す価値のある語を、LLM に優先順位付きで並べてもらう。

## 入力と出力

- 入力：
  - 拡張語彙文に実際に出てきた、手札外語彙の語（＝候補）
  - 候補ごとの出現回数（プログラムで集計）
  - 候補が出てきた文生成の履歴（原文・手札語彙文・拡張語彙文・両方のコメント・その文生成で使った手札外語彙の語）
- 出力：候補の順位、それぞれの簡潔な選定理由、根拠になった履歴（文生成の番号）

## 決まったこと

- **候補は、拡張語彙文に実際に出てきた手札外語彙の語だけ。** 以前に手札語彙から外した語も手札外語彙に戻るので、拡張語彙文に再び出てくれば候補になる。
- **まずプログラムで出現回数を集計する。** 1つの文生成で同じ語が何回出ても1回と数える。集計するのは、その言語の**直近の一定件数**の文生成だけ（件数は `parameters.md`）。今の関心に追いつきやすくするため。
- **次に LLM に順位を付けさせる。** 出現回数だけでなく、次のことを総合的に考えさせる。
  - 今の手札語彙では言いにくかったニュアンスを補えるか
  - ユーザーがこれからも使いそうな語か

  例：手札語彙の `dire`（言う）で「質問される」を言い表していた履歴があれば、手札外語彙の `chiedere`（尋ねる）がどれだけ役立つかを、原文・手札語彙文・拡張語彙文・コメントから判断させる。
- **点数は付けさせない。** 0〜100点のような採点や、原文を意味の要素に分解することはしない。出力は順位・理由・根拠の履歴だけ。
- **LLM には、今の手札語彙の一覧も渡す。** `hear` と `listen` のような似た語を両方入れてしまうことや、辞書形の取り違え（旧版の `mieux→bien` のような誤り）を、順位付けの段階で避けやすくするため。
- **足す語の意味と品詞は、旧版と同じく、文生成のときに AI が付けたものを使う。** 文生成では、各語の辞書形の辞書的な意味（文の中での意味ではない）と品詞を付けさせている。その語が最後に出てきた文生成の値を使う。
- 判断のぶれや費用を抑えるプロンプトは、実験を通して調整する。
