# 調整できる数値

語彙更新の数値は、コードの設定ファイル（`src/features/vocab-ops/vocab-ops-settings.ts`）に、この表と同じ値で置く。ただし、設定の画面で言語ごとに選ぶもの（拡張語彙文の手札外語彙の語の数の上限、語彙更新の幅）は、`languages` の表に置く。本文（01〜06）には数値を書かず、ここを指す。値を変えたら「変更履歴」に理由とともに残す。

まずは単純な方法で作り、実際の履歴・費用・LLM の判定結果を見ながら、少しずつ調整する。

| 項目 | 今の値 | 状態 | 使う場所 |
|---|---|---|---|
| 語彙更新の実行の間隔 | 文生成 30 回ごと（言語ごと） | 初期方針 | README |
| 拡張語彙文の手札外語彙の語の数の上限 | 5 | 仮 | 01 |
| 追加候補の出現回数を集計する直近の件数 | 30 件 | 仮 | 02 |
| 削除判定に必要な、手札語彙に入ってからの文生成回数 | 90 回 | 仮 | 03 |
| 削除判定の直近の集計期間 | 60 回 | 仮 | 03 |
| 削除判定の使用回数のしきい値 | 0 回 | 仮 | 03 |
| 語彙更新の幅（1回の語彙更新で増やす・減らす語数と、入れ替える語数の上限。同じ数） | 設定の画面で言語ごとに 3・4・5 語から選ぶ。初期値は 4 語 | 初期方針 | 04 |
| 語彙更新検証に使う履歴の数 | 30 件（入れ替える語が関係する履歴を先に選び、足りない分を直近30件とそれより前から 20 対 10 の割合で無作為に選ぶ） | 仮 | 05 |
| 語彙更新検証の合格の基準（増減モードごと） | 増やす：悪化が比較した件数の 25% 以下（減らすは検証しない）。変えない：改善が悪化より 2 件以上多い | 仮（判定のぶれを測ってから決め直す） | 05 |
| 1回の語彙更新の費用の上限（追加候補の順位付け、語彙更新検証のための文生成、比較判定をすべて含む） | 40 円 | 初期方針 | 02、05 |

参考：通常の文生成は、旧版の実測で1回あたり約0.3〜0.4円。

## 変更履歴

| 日付 | 項目 | 変更 | 理由 |
|---|---|---|---|
| 2026-10-18 | （初版） | — | 方針から初期値を設定 |
| 2026-10-18 | 1回に足す・外す語数の上限 | 未定 → 足す5・外す5 | 30回の文生成ごとに最大5語を覚えるペースとして |
| 2026-10-18 | 追加候補の出現回数を集計する直近の件数 | 未定 → 30 件 | 語彙更新の実行の間隔（30回）とそろえ、前回の語彙更新からあとの文生成を見るため |
| 2026-10-18 | 語彙更新検証に使う履歴の数 | 未定 → 30 件（直近30件から20件、それより前から10件） | 直近の履歴だけでなく、それより前の履歴も混ぜて、いろいろな履歴で確かめるため。それより前の文生成が10件に満たないときは、あるだけ使う |
| 2026-10-18 | 語彙更新検証の合格の基準 | 未定 → 仮の値 | 判定のぶれを測る前に動かし始めるため。ぶれを測ったら決め直す |
| 2026-10-19 | 1回に足す・外す語数の上限 | 足す5・外す5 → 増減の幅 3 語と、入れ替えの上限 3 語 | 「増やす」で ＋5 −5 の差し引き 0 の更新案ができ、増えなかったため。増やす：＋3（削除候補があれば −3 ＋6）、変えない：−3 ＋3、減らす：−3（外すだけ）とし、モードの通りに必ず増える・変わらない・減るようにした |
| 2026-10-19 | 増減の幅と入れ替えの上限 | どちらも 3 語（コードの固定値） → 語彙更新の幅として1つにまとめ、設定の画面で言語ごとに 3・4・5 語から選ぶ（初期値 4 語） | 1回に覚える語数の負担を、言語ごとに自分で決められるようにするため。幅が大きいほど1回の語彙更新で変わる語が増え（5 語の「増やす」なら −5 ＋10）、良い語と良くない語が混ざって語彙更新検証で見送られやすくなる |
| 2026-10-19 | 語彙更新検証に使う履歴の選び方 | 無作為 → 入れ替える語が関係する履歴を先に選ぶ | 無作為だと、差の多くが文生成のぶれになっていたため（`experiments/2026-10-19-judge-prompt.md`） |
