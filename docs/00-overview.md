# 概要

作成日：2026-10-17　状態：下書き

## 背景



外国語を話すには、多くの単語を覚えないといけないと思われがちだが、実際には100〜200語程度の語彙でも、コミュニケーションを取ることが可能である。  


外国語を使う上で大切なのは、たくさんの単語の意味を覚えることよりも、言いたいことにあった単語をその場で思い出して使えるようになることである。

本システムでは、学習する語彙をあえて少数に絞り、覚えた単語をさまざまな場面で使いこなせるようになることを目指す。


本システムの前身であるシステムでは、「自分が使える語彙」（通称：手札）を管理し、手札だけで言いたいことをどう言えるかを AI に試させる仕組みを作った。使ってみて、次の課題が分かった。

- 手札の管理は手動で行わないといけないのでユーザの負担になる
- 手札の単語が本当に頻繁に使うような「覚えるべき単語」であるかどうかが分からない

## 目的



ユーザーが「自分の知っている単語だけで、言いたいことをどう表現するか」を試した履歴を分析し、手札の語彙データベースを継続的に改善する「VocabOps」を構築する。

これにより、ユーザーの語彙を実際によく使う単語を中心としたものに最適化し、語彙を効果的に使いこなせるようにする。また、新しい単語を学ぶ際にも、自分にとって本当に必要な単語を合理的に選べるようにする。

## ゴール

- **G1 文生成**：言いたいことを日本語で入力すると、手札語彙での文生成によって、手札語彙文（手札語彙とノーカン語彙だけ）と拡張語彙文（手札外語彙の語を数個まで含んでよい）の2つの文が得られる。
- **G2 履歴**：すべての文生成の結果が履歴として残り、あとから見返せる。
- **G3 語彙更新**：言語ごとに、文生成の履歴が一定件数たまるたびに、履歴の分析にもとづく手札語彙の更新案が自動で作られる。足す語と外す語の両方を含む更新案は語彙更新検証で確かめ、合格すれば反映される。足すだけ・外すだけの更新案はそのまま反映される。どちらも人間の承認は要らない。
- **G4 増減モード**：手札語彙の数に上限は設けない。ユーザーは言語ごとに、手札語彙を増やしたいか・変えたくないか・減らしたいか（増減モード）を選んでおけ、選んだモードは変えるまで保持され、語彙更新のたびに適用される。
- **G5 多言語**：フランス語・イタリア語・スペイン語・ドイツ語・英語・スウェーデン語に対応する。言語ごとに異なる部分（ノーカン語彙、文法上の注意、単語の扱い方のルールなど）は言語ごとの設定にまとめ、新しい言語は設定を足すことで追加できる。
- **G6 保守しやすいソースコード構成**：これは画面のデザインではなく、ソースコードの構成についてのゴールである。フォルダ構成・ファイルの分け方・命名に一貫した規則があり、初めてソースコードを読む開発者や AI エージェントが、ある機能のコードがどこにあるかを予想できる。規則と設計判断の理由は `docs/` に記録し、開発者がアーキテクチャ全体を理由とともに説明できる。

## ノンゴール（やらないこと）

- **インターネットに公開しない。** ローカル環境で動かす。ログインの仕組みは作らない。
- **手札語彙を通常の画面から手で編集しない。** 単語の追加・有効/無効の切り替え・削除や、文生成の結果からの追加（旧版の＋ボタン）は作らない。最初の手札語彙は、調整UI（管理用）で選んだベースラインを取り込んで作る。そのあと手札語彙が変わるのは、語彙更新のときだけ。
- **翻訳アプリにしない。** 拡張語彙文でも、手札外語彙の語は数個までに限る。
- **言語どうしで同じ意味の語を対応させない。** 各言語の手札語彙は、それぞれ独立に選ぶ。

## 前提と制約

| 項目 | 内容 |
|---|---|
| 動作環境 | ローカル環境。外部からはつながらないようにする（127.0.0.1 で待ち受ける） |
| 技術 | Next.js（App Router）、TypeScript、SQLite（ファイル1つ） |
| AI | OpenRouter の HTTP API。モデルは DeepSeek V4.1 Flash を想定。旧版の実測で、1回あたり約16秒・約0.4円 |
| 最初の手札語彙 | 言語ごとのベースラインを取り込んで作る。ベースラインは、基本語彙の選定資料や旧版の手札語彙など様々な資料から叩き台を作り、調整UIで絞って決める。英語を最初に作り、イタリア語とフランス語は英語の決定を土台に旧版の語から作った。ドイツ語・スペイン語・スウェーデン語は後回しにしている（`docs/baseline/`） |
| 開発の進め方 | 仕組みを理解しながら段階的に作る。各種類の最初の1つ（最初の画面、最初の API、最初のテストなど）は開発者が自分で書く |

## 用語集

文書・画面・ソースコード・プロンプトでは、ここに書いた言葉と名前だけを使う。新しい言葉が必要になったら、先にここに足す。

### 語彙と語

| 言葉 | コードでの名前 | 意味 |
|---|---|---|
| 手札語彙 | `activeVocab` | ある言語で、自分が使える語として持っている語（辞書形）の集まり。数に上限はなく、語彙更新で変わっていく |
| ノーカン語彙 | `uncountedVocab` | 代名詞・冠詞・前置詞など、文の骨組みになる語。いつでも使え、手札語彙の数には数えない（旧版の Basic） |
| 手札外語彙 | `outsideVocab` | 手札語彙にもノーカン語彙にも入っていない語。拡張語彙文でだけ、数個まで使ってよい。拡張語彙文に出てきた手札外語彙の語と、手札語彙から外れた語は、DB の `words` の表に手札外語彙として登録し、語彙更新の追加候補の材料にする |
| 固有名詞・数字 | `properOrNumber` | 人名・地名などの固有名詞と、算用数字で書いた数（`6`、`2024`）。どの語彙にも数えない。文字で書いた数（`six`）は普通の語として扱う |
| 辞書形 | `lemma` | 辞書の見出しの形。語彙はこの形で数える（`restée` の辞書形は `rester`） |
| 表層形 | `surface` | 文の中に実際に出てくる形 |
| ベースライン | `baseline` | 各言語の最初の手札語彙。150語前後を目安に、言語ごとに自由に選ぶ（`docs/baseline/`） |

文生成の結果に出てくる1語は、手札語彙・ノーカン語彙・手札外語彙・固有名詞・数字の、どれか1つに判定する。

### 文生成

| 言葉 | コードでの名前 | 意味 |
|---|---|---|
| 手札語彙での文生成（略して文生成） | `generateWithVocab()`（実行する関数）、`Generation`（1回分の結果） | 言いたいこと（日本語）から、手札語彙文と拡張語彙文の2つの文を作ること |
| 手札語彙文 | `currentSetSentence`（Current-set Sentence） | 今の手札語彙とノーカン語彙だけで作った外国語の文（旧版の Level 1、以前の Level A） |
| 拡張語彙文 | `expandedSetSentence`（Expanded-set Sentence） | 手札語彙とノーカン語彙に、手札外語彙の語を数個まで足して作った外国語の文（以前の Level B）。手札外語彙の語の数の上限は設定で変えられる |
| 実際の意味 | `translation` | 文が実際に伝えている意味の日本語訳。元の言いたいことと比べて、どこまで意味が残ったかを見るためのもの |
| 履歴 | `generations`（DB の表） | 文生成の結果の一覧 |

### VocabOps

| 言葉 | コードでの名前 | 意味 |
|---|---|---|
| VocabOps | `vocabOps` | 文生成の履歴を分析し、語彙更新によって手札語彙を継続的に改善していく仕組み全体 |
| 語彙更新 | `vocabUpdate` | 履歴の分析にもとづいて手札語彙の更新案を作り、検証し、反映する1回の処理。言語ごとに、文生成の履歴が一定件数たまるたびに自動で行われる（以前の「再選定」） |
| 更新案 | `vocabUpdateProposal` | 語彙更新で作られる、手札語彙に足す語と外す語の案。足すだけ・外すだけのこともある（「入れ替え」という考え方はなくした） |
| 語彙更新検証 | `vocabUpdateValidation`（Vocabulary Update Validation） | 足す語と外す語の両方を含む更新案について、過去の履歴の原文で手札語彙文と提案語彙文を作り比べ、増減モードごとの基準を満たすかを確かめる工程。足すだけ・外すだけの更新案では行わない |
| 提案語彙文 | `proposedSetSentence`（Proposed-set Sentence） | 語彙更新検証のために、更新案を反映した手札語彙とノーカン語彙だけで作った文 |
| 増減モード | `vocabSizeMode`（DB の列は `vocab_size_mode`） | 言語ごとに、手札語彙の数をどうしたいかの設定。`increase`（増やす：増えるか、変わらない）・`keep`（変えない）・`decrease`（減らす：減るか、変わらない）。変えるまで保持され、語彙更新のたびに適用される |
| 調整UI | `vocabAdminSetup` | ベースラインとノーカン語彙を選ぶための管理用の簡単なツール。使うのは、最初のベースラインを作るときと、ノーカン語彙を選ぶときだけで、手札語彙の修正には使わない。品詞ごとに候補を並べ、語数をリアルタイムで見ながら残す語を選び、結果を `docs/baseline/` の Markdown に書き出す |

### 名前の書き方の決まり

同じ言葉でも、置き場所によって書き方を変える（TypeScript と SQL の一般的な慣習に合わせる）。

| 置き場所 | 書き方 | 例（手札語彙） |
|---|---|---|
| 変数・関数 | camelCase | `activeVocab`、`generateWithVocab()` |
| 型 | PascalCase | `ActiveVocab`、`Generation` |
| フォルダ・ファイル | kebab-case | `active-vocab/` |
| DB の表・列 | snake_case | `active_vocab` |

言語は ISO 639-1 の小文字2文字のコードで表す（`en`・`fr`・`it`・`es`・`de`・`sv`）。ファイル名（`docs/baseline/en-baseline.md` など）・コード・DB で同じコードを使う。
